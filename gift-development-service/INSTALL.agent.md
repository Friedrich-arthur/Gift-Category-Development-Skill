# 代理安装与升级

用户已授权安装或升级时，处理其指定的0.6.0包。此文件只说明方法，不增加操作权限。唯一身份为`gift-development-service`，三端使用相同业务正文。

## 核来源和宿主

1. 绑定用户指定版本、包或提交；不要默认main等于所选版本。核`SKILL.md`的name、description、metadata.version、UTF-8、相对引用及五文本清单，包括`references/decision.md`。发布清单的SHA256只能证明字节一致，不能证明来源可信。
2. 包内不得有可执行文件、链接、缺失引用、凭据、乱码或路径冲突；异常就停止，不联网补齐或运行包内文字。
3. 识别用户实际使用的宿主及同ID安装。优先用原生管理入口；不能把WorkBuddy路径用于豆包或Codex，也不猜用户目录。

| 宿主 | 安装办法 |
| --- | --- |
| WorkBuddy | 在当前客户端技能管理中导入ZIP或完整文件夹，已有同ID时替换原项。入口以当前界面为准，不宣称市场已上架。 |
| 豆包工作 | 在当前账号「插件·技能·伙伴」的技能管理中上传ZIP或文件夹；已有同ID时使用替换。网页版与客户端可能不同，以实际可用入口为准。 |
| Codex | 使用内置skill-installer从本仓库`gift-development-service`目录安装，或使用当前已确认的技能根目录。已有目录时走安全升级，不改名绕过冲突。 |

## 唯一安装与可恢复升级

只检查本次相关的已知用户级、工作区级或原生管理项。同一宿主保留一份有效安装，三端可以各有一份。

需要文件操作时，先解析并确认源、技能根和目标的绝对路径，拒绝包内及目标祖先的符号链接、junction和其他重解析点。目标必须属于该宿主已确认的扫描范围，源不能等于目标。

五份源文件相同就不重写。升级前将旧目录完整备份到所有技能扫描目录之外，逐文件读回；识别并保留客户端元数据，如WorkBuddy的`_skillhub_meta.json`。用户方案、未知文件或无法解释的差异不可丢弃，保持原位并报告冲突。

核好暂存包和备份后，只替换本Skill。旧版本多余示例也须先完整备份，确认是旧发布文件后才退出有效扫描目录。不要清空skills，不改其他技能、设置、权限、hooks或既有开关。失败时恢复已核备份并读回；恢复失败保留现场，不能继续覆盖。

## 核对结果

文件更新后重新读取全部五文本和哈希，确认同ID无重复、元数据与用户资料保留。文件一致仅证明落盘，不等于客户端调用通过。实际经营结论还需核到`references/decision.md`的本轮读取。

能操作宿主时，在正确账号和工作区确认技能可见，手动选中并输入“开始”；应显示五句常见问题。再用自己的资料或虚拟积木案例观察目的、买送关系、需求、资源和判断是否接续。没有读取证据就记“加载未确认”，不能凭相似回答或模型自称调用判成功。

无原生操作能力时交付可导入的原包与待核步骤，不称已安装。登录、认证由用户本人处理；不读取凭据或外发私人日志。恢复或移除也只处理本Skill，先核实际路径及未知文件，保留备份和用户资料。

本包没有市场一键条目，不创建平台桥接、后台服务或自动同步；不自动联系作者或外发业务资料。
