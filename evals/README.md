# 咨询行为评测

目标是让用户在自己的目的、送礼关系、消费者需求和资源范围内，作出一个可解释的礼品经营判断。

| 用例 | 轮数 | 观察什么 |
| --- | --- | --- |
| `consultation-main.json` | 5 | 目的不明→买送关系→消费者与候选→评论和资源→条件变化后的经营结论 |
| `boundaries.json` | 每例2轮，共6轮 | 目的优先；兴趣不等于MOQ投入；样盒确认不等于完整可售 |
| 开场 | 2 | 先输入“开始”，再输入“没有资料”，五句菜单只出现一次，之后只问经营目的 |
| `transfer.json` | 3 | 更换产品和参数，整份重量待核→超限→用户更正为符合；只更新对应条件 |

运行每个案例时用独立的新对话，先通过宿主正常选择本Skill。代理代偿时显式读取同一冻结正文与按需资源，记录实际模型和配置。同一案例逐条发送，不预先交付后续轮次。

业务代理只收到本轮原题，不能看到判据、期望答案或已知缺陷。`boundary-rubric.md`、`consultation-rubric.md`仅给独立评审；不要把evals目录装进用户Skill。

保存完整回应及可见中间消息，核实际加载链；模型自称“已读”不是证据。子代理消息体无法明文回读时单独说明，不把发送动作说成逐字读回。对原题、正文、配置或判据的变化分别冻结，不拼接不同配置的局部PASS。

按六项业务结果审完整五轮，全部PASS且无硬失败才能通过。再用不同产品和参数检查本体／整份范围、已知与未知、底线等号、窗口端点及改判，避免只修到固定例题。

当前用例沿用已有原题；主线判据只迁移了相对引用，评分语义未变。运行原文、调试记录与历次修订保存在私有审计归档，不进入本公开源码仓。[本版验证范围](../docs/VERIFICATION.md)区分维护检查、受控回放、客户端原生和真人采用。
